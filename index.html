OPEN-SOURCE PROJECT REPORT

Job Application Tracker

Automatically collect job application confirmation emails from Gmail and organize them in Google Sheets.

Google Apps ScriptGmail APIGoogle SheetsRead-only Gmail access
Project status: working prototype

The initial import has successfully written records to the spreadsheet in batches of 10. Historical coverage, extraction accuracy, and automated scheduling still need validation before this should be treated as a complete tracker.

1. Overview

Job applications often generate confirmation emails from employers, applicant-tracking systems, and job platforms. Manually copying each confirmation into a tracker is repetitive and makes it easy to miss applications.

This project uses Gmail search and the Gmail API to find likely application messages, extracts basic metadata, and appends records to a Google Sheet. It is designed to avoid duplicate imports by storing each Gmail message ID.

2. Goals

  • Collect application-related emails from Gmail.
  • Record application date, company, position, source, status, last communication, and email subject.
  • Import historical messages in small batches to reduce API quota pressure.
  • Prevent duplicate rows using the unique Gmail message ID.
  • Keep Gmail access read-only; the script does not need permission to send or delete email.

3. Architecture

The Advanced Gmail API is used instead of the broad GmailApp service. The intended OAuth scopes are:

  • https://www.googleapis.com/auth/gmail.readonly
  • https://www.googleapis.com/auth/spreadsheets.currentonly

4. Spreadsheet schema

The simplified Applications worksheet uses eight columns:

AEmail IDUnique Gmail message ID; used for deduplication.
BApplication DateDate/time the message was received.
CCompanyBest-effort company estimate; may need review.
DPositionBest-effort title extracted from the subject.
ESourceLinkedIn or Company / Other.
FStatusInitially set to “Applied - needs review”.

Location, Job URL, Contact Person, Contact Email, and Follow-up Date were removed from the requested layout.

5. Historical import and batching

Gmail API quota limits were encountered when the script fetched too many individual messages in a short period. The import was therefore reduced to batches of up to 10 messages per execution.

The script stores a Gmail page token in Apps Script Properties and resumes from that token on the next run. Existing message IDs are loaded from the sheet before writing, preventing already-imported messages from being appended again.

Target historical window

The requested coverage is the last six years (a rolling six-year window). For a run on 16 November 2026, that is approximately 16 November 2020 onward. Use Gmail's newer_than:6y search operator when starting a fresh six-year search.

Important: Do not change the Gmail query while a paginated import is in progress. Finish the current run first. If the query is changed, reset the saved pagination token and completion flag deliberately, then restart from the first page. Keep the sheet's Email ID deduplication check in place.

At the point captured in the project notes, the script had imported batches successfully, but visible rows were still dated in 2026. That does not prove older mail is absent; the import must continue through subsequent pages and the oldest imported date must be checked.

6. Current extraction logic

  • Application date: derived from Gmail's internal message timestamp.
  • Company: estimated from the sender's email domain.
  • Position: extracted from a small set of subject-line patterns.
  • Source: classified as LinkedIn when the sender or message content contains “LinkedIn”; otherwise Company / Other.
  • Status: initialized to “Applied - needs review”.

This is intentionally a first-pass parser. Sender domains such as Workday or Greenhouse often identify the applicant-tracking provider rather than the employer. Many confirmation emails also have different subject wording or HTML-only bodies.

7. Known limitations and risks

  • Search coverage: the current Gmail query looks for a limited set of subject phrases. It can miss confirmations with other wording, or include unrelated messages.
  • Company accuracy: domain-based extraction can return the ATS provider rather than the hiring company.
  • Position accuracy: title extraction only checks the subject, so many titles will remain “Needs review”.
  • Body parsing: MIME structures vary; some parts may have no inline body data, and HTML-only messages may not be parsed into useful text.
  • Quota limits: a six-year import may require many executions. Wait and retry after quota errors.
  • Message versus thread: the script records individual messages, not necessarily one consolidated application conversation. Follow-up emails can therefore create additional rows if they match the search.
  • Privacy: email contents are processed by the user's Google Apps Script project and written to their own spreadsheet. Avoid publishing personal email data, message IDs, or logs in the public repository.

8. Setup summary

  1. Create a Google Sheet named Job Application Tracker and a tab named Applications.
  2. Add the eight headers listed above in row 1.
  3. Open Extensions → Apps Script.
  4. Enable the Advanced Gmail service (Gmail API v1).
  5. Configure the manifest with the two read-only/current-spreadsheet OAuth scopes listed in this report.
  6. Add the Apps Script importer and helper functions.
  7. Run the importer and review the authorization prompt carefully.
  8. Run repeated batches until the import reports completion; verify the oldest date is within the six-year window.

Google may require enabling the Gmail API in the associated Google Cloud project as well as adding it as an Apps Script advanced service.
